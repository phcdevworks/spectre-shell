## What this package is

`@phcdevworks/spectre-shell` is the thin bootstrap layer for Spectre apps. It wires a root DOM element to route definitions, starts the router, loads shared shell styles, and exposes a `bootReady` readiness signal. That is the full scope — no more.

## Commands

```bash
npm run check        # typecheck + lint + build + test (run before every commit)
npm run typecheck    # tsc --noEmit only
```

All pre-publish validation runs through `npm run check`. The CI workflow runs the same command on Node 22 and Node 24.

## Architecture

```
src/
  index.ts       — public barrel: re-exports bootstrapApp, bootReady, BootstrapOptions
  bootstrap.ts   — core logic: lifecycle hooks, route collection, router handoff, bootReady signal
  styles.ts      — side-effect import of spectre-tokens and spectre-ui CSS
  css.d.ts       — declare module '*.css' for TypeScript
tests/
  bootstrap.test.ts — full Vitest suite (12 tests covering orchestration, errors, hooks, signal state)
dist/            — built output (committed only for releases, generated by tsc)
```

## Bootstrap execution order

1. `beforeMount()` — optional pre-route callback
2. `routes()` — factory called; routes collected
3. `new Router(routes, root)` — hands routing to `@phcdevworks/spectre-shell-router`
4. `bootReady.value = true` — signals successful startup
5. `afterMount()` — optional post-startup callback (runs after `bootReady` is set)

Steps 1–4 are wrapped in a try/catch. Failures throw `[spectre-shell] Bootstrap failed: <message>` with the original error as `cause`. `afterMount` is intentionally outside the error boundary — if it fires, bootstrap succeeded.

## Public API

```ts
bootstrapApp(options: BootstrapOptions): void
bootReady: Signal<boolean>

type BootstrapOptions = {
  root: HTMLElement
  routes: () => Route[]         // Route from @phcdevworks/spectre-shell-router
  beforeMount?: () => void
  afterMount?: () => void
}
```

## Package boundaries — what belongs here vs. elsewhere

| Concern | Owner |
|---|---|
| Bootstrap flow, root mounting, readiness signal | **this package** |
| Route matching, navigation, lifecycle sequencing | `@phcdevworks/spectre-shell-router` |
| Reactive signal primitives | `@phcdevworks/spectre-shell-signals` |
| Design tokens, CSS custom properties | `@phcdevworks/spectre-tokens` |
| Reusable UI styles | `@phcdevworks/spectre-ui` |
| App state, feature logic, domain behavior | downstream apps |

## Development rules

- Keep the exported surface small: `bootstrapApp`, `bootReady`, `BootstrapOptions`.
- Do not add routing logic, reactive primitives, tokens, or styling to this package.
- Keep the package framework-agnostic — vanilla TypeScript only, no framework imports.
- Every public behavior change needs a test and a CHANGELOG entry.
- Run `npm run check` before committing; CI enforces the same gate.
- Use `npm run clean && npm run build` when debugging dist output.
- Prefer editing existing files over creating new ones.
- Keep `ROADMAP.md` and `TODO.md` current — mark items done when they ship.
- Comments only for non-obvious constraints or workarounds. Never explain what code does.
