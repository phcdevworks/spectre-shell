**Package:** `@phcdevworks/spectre-shell`
**Human owner:** Bradley Potts (brad.potts@coastdigitalgroup.com)
**Primary AI developer:** Claude Code (claude-sonnet-4-6)

`@phcdevworks/spectre-shell` is the thin bootstrap layer for Spectre apps. It
wires a root DOM element to route definitions, starts the router, loads shared
shell styles, and exposes a `bootReady` readiness signal. That is the full
scope - no more.

This file is the authoritative guide for Claude Code operating in this
repository. Read it before touching any source file.

## Architecture

```
src/
  index.ts       - public barrel: re-exports bootstrapApp, bootReady, BootstrapOptions
  bootstrap.ts   - core logic: lifecycle hooks, route collection, router handoff, bootReady signal
  styles.ts      - side-effect import of spectre-tokens and spectre-ui CSS
  css.d.ts       - declare module '*.css' for TypeScript
tests/
  bootstrap.test.ts - full Vitest suite (12 tests covering orchestration, errors, hooks, signal state)
dist/            - built output (committed only for releases, generated by tsc)
```

## Bootstrap Execution Order

1. `beforeMount()` - optional pre-route callback
2. `routes()` - factory called; routes collected
3. `new Router(routes, root)` - hands routing to `@phcdevworks/spectre-shell-router`
4. `bootReady.value = true` - signals successful startup
5. `afterMount()` - optional post-startup callback (runs after `bootReady` is set)

Steps 1-4 are wrapped in a try/catch. Failures throw
`[spectre-shell] Bootstrap failed: <message>` with the original error as
`cause`. `afterMount` is intentionally outside the error boundary - if it
fires, bootstrap succeeded.

## Public API

```ts
bootstrapApp(options: BootstrapOptions): void
bootReady: Signal<boolean>

type BootstrapOptions = {
  root: HTMLElement
  routes: () => Route[]         // Route from @phcdevworks/spectre-shell-router
  beforeMount?: () => void
  afterMount?: () => void
}
```

## Versioning and Releasing

This package follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Update `CHANGELOG.md` under `[Unreleased]` as you work.

Claude Code's release prep:

1. Move `[Unreleased]` entries under the new version header.
2. Bump `version` in `package.json`.
3. Run `npm run check` - must be clean.

`release:propose` (`scripts/propose-version.js`) reads the release impact from
`CHANGELOG.md [Unreleased]` and proposes the version bump. Bradley Potts
retains final version authority.

Codex reviews release readiness against the `CODEX.md` checklist. Bradley
creates the tag, commits, and pushes.

`prepublishOnly` runs `npm run check` automatically on `npm publish`.

## What This Package Does Not Own

Shared working boundaries live in `AGENTS.md`. Claude Code must keep this
package focused on bootstrap orchestration only:

- Token meaning and design values belong in `@phcdevworks/spectre-tokens`.
- Reusable CSS and UI primitives belong in `@phcdevworks/spectre-ui`.
- Route matching, navigation, and lifecycle sequencing belong in
  `@phcdevworks/spectre-shell-router`.
- Reactive signal primitives belong in `@phcdevworks/spectre-shell-signals`.
- App state, feature logic, and domain behavior belong in downstream apps.
