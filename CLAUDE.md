## Bootstrap Execution Order

1. `bootReady.value = false` — resets readiness for the latest bootstrap attempt.
2. `beforeMount()` — optional pre-route callback
3. `plugins[].install({ bootReady })` — optional plugins run in declaration order
4. `routes()` — factory called; routes collected
5. `new Router(routes, root, routerOptions)` — hands routing to `@phcdevworks/spectre-shell-router`
6. `bootReady.value = true` — signals successful synchronous shell startup
7. `afterMount()` — optional callback runs after router construction and readiness

Steps 1–6 are wrapped in a try/catch. Synchronous failures throw
`[spectre-shell] Bootstrap failed: <message>` with the original error as
`cause`. `afterMount` is outside the error boundary; if it throws, readiness
remains true.

Initial route rendering is asynchronous. Use `routerOptions.afterNavigate`
for rendered content and `routerOptions.onError` for navigation failures.
Neither `bootReady` nor `afterMount` waits for route rendering. Hooks and
plugin installation are synchronous and their returned promises are not awaited.
The shared signal describes the latest bootstrap attempt. Destroy an existing
router before restarting; router destruction itself does not reset readiness.

## Public API

```ts
bootstrapApp(options: BootstrapOptions): Router
bootReady: Signal<boolean>

type BootstrapOptions = {
  root: HTMLElement
  routes: () => Route[]         // Route from @phcdevworks/spectre-shell-router
  beforeMount?: () => void
  afterMount?: () => void
  plugins?: ShellPlugin[]
  routerOptions?: RouterOptions // from @phcdevworks/spectre-shell-router
}

type ShellPlugin = {
  name: string
  install: (context: ShellPluginContext) => void
}

type ShellPluginContext = {
  bootReady: Signal<boolean>
}
```
