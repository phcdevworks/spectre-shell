## Architecture

```
src/
  index.ts       - public barrel: re-exports the bootstrap API and Router type
  bootstrap.ts   - core logic: lifecycle hooks, route collection, router handoff, bootReady signal
  styles.ts      - side-effect import of spectre-tokens and spectre-ui CSS
  css.d.ts       - declare module '*.css' for TypeScript
tests/
  bootstrap.test.ts - full Vitest suite covering orchestration, plugins, errors, hooks, and signal state
dist/            - built output (committed only for releases, generated by tsc)
```

## Bootstrap Execution Order

1. `beforeMount()` - optional pre-route callback
2. `plugins[].install({ bootReady })` - optional plugins run in declaration order
3. `routes()` - factory called; routes collected
4. `new Router(routes, root)` - hands routing to `@phcdevworks/spectre-shell-router`
5. `bootReady.value = true` - signals successful startup
6. `afterMount()` - optional post-startup callback (runs after `bootReady` is set)

Steps 1-5 are wrapped in a try/catch. Failures throw
`[spectre-shell] Bootstrap failed: <message>` with the original error as
`cause`. `afterMount` is intentionally outside the error boundary - if it
fires, bootstrap succeeded.

## Public API

```ts
bootstrapApp(options: BootstrapOptions): Router
bootReady: Signal<boolean>

type BootstrapOptions = {
  root: HTMLElement
  routes: () => Route[]         // Route from @phcdevworks/spectre-shell-router
  beforeMount?: () => void
  afterMount?: () => void
  plugins?: ShellPlugin[]
}

type ShellPlugin = {
  name: string
  install: (context: ShellPluginContext) => void
}

type ShellPluginContext = {
  bootReady: Signal<boolean>
}
```
